The full graph includes native and archived notes, code/config/test/migration stubs, public interface operations, modules, tasks, requirements, APIs, IPC endpoints, commands/tools, context flows, completion gates, security profiles, learnings and six declared synergy clusters. Literal native links use Obsidian’s resolved/unresolved metadata; URI and portable Markdown links retain their source location. Boundary references are labelled, not silently scanned. Identical copies remain distinct facet files with explicit content-identity connections.

Graphify 0.9.57 supplies actual local structural extraction of selected code sources and community detection/export. Comment stubs, maintenance code and separate reference examples retain separate scopes. Prose is mapped through explicit links and declared structured owners, not an unbounded LLM semantic pass. Images/PDFs and other binary artifacts receive file identity and references, without claiming visual or semantic extraction. Querying a node is a route to source, not a substitute for reading its controlling contract.

`EXTRACTED` and `INFERRED` describe relationship evidence; `_origin` separately records the producer. A local AST resolver can infer a connection without any LLM. Same-endpoint relations and reverse links remain separate in the canonical MultiDiGraph. Graphify’s simple-graph rebuild can collapse these; do not run `graphify update` or `cluster-only` over this combined graph. Clustering uses a labelled undirected simple analysis projection, and cannot amend the six declared module clusters. The small overview/canvas deliberately omits lower-level nodes; full JSON and tree retain the complete inventory.

## Update, verify, repair, reverify

1. Follow the completion/update protocol and record actual module/source/test/hardening observations without promoting them to admission.
2. Update the narrow owning records or generators; preserve implementation bodies, migration history and the operator coding boundary.
3. Run `./tools/corpus-sync --verify-tooling` after maintenance changes.
4. Run `./tools/corpus-sync` (or the reviewed Justfile `corpus-update`). It publishes and verifies the core corpus, then builds Graphify from a frozen copy of that completed generation. Graphify performs local analysis only.
5. Require `./tools/corpus-sync --check` (or `just corpus-check`) to pass both the core corpus and all three exact graph copies, source identities and graph provenance. Missing/stale/interrupted graphs fail the overall check.
6. If only graph building was interrupted, use `./tools/corpus-sync --graph` after the core publication is complete. This rebuilds derived artifacts from the current core, without replaying engine effects. Previous frozen graph generations remain in the review directory. Changed authored graph output is refused until its owner is reconciled.
7. Retain the independent graph readback and bounded query results; update the handoff. A library/environment failure remains explicit, never a synthetic PASS.

The host Graphify tool environment is required for this analysis step. No PATH edit, global installation, Git hook, watcher, new registry, provider call or persistent default-model change is made. Graph artifacts are excluded from their own source set, preventing recursive graph-of-graph growth. They have per-file atomic copies and a last-written receipt; the cross-filesystem update is not one transaction. Recheck all inputs after analysis and refuse concurrent source changes.

## Bounded navigation commands

Run in the host terminal; these query the derived graph only. The current full graph exceeds the installed 512 MiB default file cap; the maintenance runner sets `GRAPHIFY_MAX_GRAPH_BYTES=1073741824` (1 GiB, raised from 640 MiB on 2026-09-21 when graph.json reached 728 MB). Use the explicitly bounded 640 MiB cap for each query; this is a file-size limit, not a memory-use guarantee. Keep this setting process-local and refuse a graph exceeding it until its source and resource requirements are reviewed:
