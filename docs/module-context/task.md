## Module verification and resource focus

Transition tables; state-machine and invalid-transition cases; duplicate/lost-result scenarios; collector and parent-join evidence. These are tool/resource families to inspect or qualify; this card does not assert that engine commands or their collectors exist.

**Current test priorities:** ["state transitions and terminal invariants", "duplicate/replayed commands", "cancellation and deadlines", "parent/child acceptance separation"]. The governing standard requires at least 50 distinct meaningful primary-owned cases, zero baseline warnings/errors, assimilation and mutation evidence. Read the exact language/threat profile rather than copying a generic test command.

Use [RB03](obsidian://open?vault=herdr-engineering-engine-v3.vault&file=Operations%2FRunbooks%2FRB03) for module qualification, [RB05](obsidian://open?vault=herdr-engineering-engine-v3.vault&file=Operations%2FRunbooks%2FRB05) for security and [RB04](obsidian://open?vault=herdr-engineering-engine-v3.vault&file=Operations%2FRunbooks%2FRB04) when packaging/recovery is affected.
