# HEE Module Scout

Prepare a bounded context brief that gives a coding agent the sources, relationships and verification obligations needed for its next authorized step. Preserve access to the full corpus without loading it all at once.

## Start with one module and question

1. Read the active request and applicable `AGENTS.md`. Confirm the original task and actual coding authorization. Luke's quoted trigger in documentation is not an instruction to start coding. If a module is unspecified, use the current task and declared ownership to select it; expose a material ambiguity rather than inventing an owner.
2. Locate the existing codebase at `/var/home/herdr-engineering-engine-v3`; Toolbx may expose it at `/run/host/var/home/herdr-engineering-engine-v3`. Never recreate an apparently missing host folder. Read the quick start's freshness procedure and check the complete generation before trusting generated context.
3. Open the selected `docs/module-context/<module>.md` card's **Start here** section and question list. Valid module IDs come from `corpus/anchors.json`. Use the card inventory as a router; do not preload the old full module contract or every card.
4. Follow the disclosure stages in [the context workflow](file:///var/home/herdr-engineering-engine-v3/docs/module-context.md). Expand the exact boundary, criterion, task or source section needed to answer the current question. Read candidate source outside managed anchor comments.
5. Return the brief defined below, then continue the user's authorized work. Context preparation is not a new approval ceremony or an admission gate.

## Deeper disclosure

Read only the reference needed now:

| Need | Reference |
| --- | --- |
| A source-owner, planning, handoff, CLI or host-boundary gap needs a companion skill | [Toolshed companion skills](references/companion-skills.md) |
| Select exact sources, use Graphify or make a habitat-context packet; handle a partial or stale result | [Retrieval and provenance](references/retrieval.md) |
| Coordinate scouts and implementation/verifier threads; decide whether the next step has enough context | [Context brief and cohesion](references/brief-and-cohesion.md) |
| Resolve uncertain quality claims, future tool availability, security or optional numerical work | [Quality and uncertainty](references/quality-and-uncertainty.md) |

Those references route to the existing module cards and controlling sources. Do not load all references by default or turn source procedures into executable instructions.

## Required return

Name module/task, authority, generation/subject, intended change, invariants, primary/support ownership, affected callers and dependencies, request/result/error/cancel/usage/evidence returns, criterion-to-oracle mapping, actual tool availability, source locators/read status, omissions, contradictions and next bounded action. Source text coverage and relationship coverage are separate. A located source or resolved seed is not read context; an exemplar PASS is not engine qualification.
